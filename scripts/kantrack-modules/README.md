# scripts/kantrack-modules/

Every feature module of the KanTrack application. Each file has one responsibility.

---

## TypeScript core (typed infrastructure)

| File            | What it does                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                               |
| --------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| `types.ts`      | Shared domain types: `Task`, `Column`, `Priority`, `Tag`, `NotebookItem` (incl. `expanded?: boolean`), `Clock`, `UndoEntry`                                                                                                                                                                                                                                                                                                                                                                                                                                                                |
| `store.ts`      | Minimal flux-like store — `dispatch()`, `subscribe()`, `getState()`, typed reducer, `TASK_*` action types                                                                                                                                                                                                                                                                                                                                                                                                                                                                                  |
| `router.ts`     | Event delegation router — `registerAction()` maps `data-action` names to handlers; `initRouter()` attaches one document-level click listener                                                                                                                                                                                                                                                                                                                                                                                                                                               |
| `repository.ts` | **All** persistence logic: `getAllTasks()`, `saveTasks()`, `getAllNotebookItems()`, etc. Writes localStorage synchronously and IDB async (300 ms debounced). `flushPendingIDBWrites()` cancels any pending timer and fires the write immediately — called on `beforeunload` and before `location.reload()`. `getNotebookItemContent()` uses a three-tier fallback: IDB → `notebookItems` localStorage → `notebookContent_<id>` per-page backup key. `saveNotebookContentBackup()` / `deleteNotebookContentBackup()` manage the backup key written on every page save and removed on delete |

## Key data flows

### Creating a task

`addNote()` (tasks.js) → `state.pushToNotesData()` → `saveNotesToLocalStorage()` → `repository.saveTasks()` → localStorage (sync) + IDB (async, 300 ms debounced)

On `beforeunload`, `flushPendingIDBWrites()` fires any pending debounced IDB write immediately so no data is lost if the tab is closed mid-debounce.

### Saving modal changes

Both paths share `_persistModalChanges()` which handles title, priority, tags, timer, and note content:

- **Save & Close:** `saveAndCloseModal()` → `_persistModalChanges()` → `saveNotesToLocalStorage()` → `updateNoteCardDisplay()` → `closeTaskModal()`
- **Save (keep open):** `saveModal()` → `_persistModalChanges()` → `saveNotesToLocalStorage()` → `updateNoteCardDisplay()` → resets tracking state + clears editor + re-renders history in place

### Done column capacity check

`updateNoteColumn()` (tasks.js) stamps `doneAt = Date.now()` on a task entering Done (clears it if the task leaves) → `checkDoneCapacity()` (done-capacity.js) → `selectDoneOverflow(state.notesData)` returns the oldest 15 Done cards once the column holds 30+ → if non-empty, a blocking `<dialog>` opens offering per-card or zipped PDF export → confirming **Delete** calls `deleteDoneOverflowTasks()`, which removes the cards from `notesData`, deletes their images, persists, purges undo/redo history referencing them, and dispatches `kantrack:taskRemoved` for each — entirely bypassing Trash and undo, by design irreversible.

`backfillDoneTimestamps()` runs once at bootstrap to stamp `doneAt` onto any pre-existing Done card that predates this feature, guarded by a `meta` flag so it never re-runs.

### Hiding and restoring a card

The eye-off button only appears on cards in **To Do** and **On Hold**; `createNoteElement()` (tasks.js) omits it for `inProgress`/`done` cards, and `hideCard()` (hidden-cards.js) is a no-op if called for those columns regardless.

Click the eye-off button on a To Do or On Hold card → `hideCard()` (hidden-cards.js) sets `hidden: true` / `hiddenAt: Date.now()`, records a `type: 'hidden'` undo entry, persists, and dispatches `kantrack:taskUpdated` + `kantrack:updateColumnCounts` + `kantrack:updateHiddenCount` → the card's column re-renders without it and the header badge (`#hiddenCount`) updates.

Click the header `#hiddenToggleBtn` → `showHiddenCardsModal()` lists every hidden, non-deleted task (most-recently-hidden first) → per-row **Show** or multi-select **Show Selected** call `showCard()` / `showCards()`, each clearing `hidden`/`hiddenAt`, recording its own undo entry, and re-rendering the card back into its original column at its original sorted position.

While searching, if any hidden tasks match the query, an inline hint (`#hiddenSearchHint`) appears below the search row — clicking **View** opens the modal pre-filtered to that query (`showHiddenCardsModal(query)`), with a "Clear filter" control to see all hidden cards again.

Hidden tasks are excluded from column rendering (`tasks.js`), column counts (`search.js`), and the Done-column 30-card cap (`done-capacity.js`) — they behave as if temporarily off-board, but remain fully intact in `notesData` and are restored undo/redo-safe even across delete/trash-restore cycles.

### Loading on startup

`loadNotesFromLocalStorage()` (storage.js) → `repository.getAllTasks()` → localStorage (primary, always written synchronously) or IDB (fallback) → `state.setNotesData()` → render all cards

### Saving a notebook page

`saveAndClosePage()` (notebook.js) → `saveNotebookContentBackup(id, html)` → `localStorage.setItem('notebookContent_<id>', html)` (sync, per-page backup key) → `saveNotebookToLocalStorage()` → `repository.saveNotebookItems()` → `localStorage.notebookItems` (sync, metadata only) + IDB `notebook_items` (async, 300 ms debounced, includes content)

On page open, `getNotebookItemContent(id)` (repository.ts) tries: IDB → `localStorage.notebookItems` → `localStorage.notebookContent_<id>`. The per-page backup ensures content is recoverable even when IDB is wiped.

## Notable bug fixes

### Tag filter buttons did nothing after a page reload (`search.js` + `tags.js`)

After a full browser reload, clicking a tag filter button had no visible effect — no tasks were filtered and the button never turned active.

**Root cause — duplicate event listeners**

The bootstrap sequence ran two listener-attachment paths over the same DOM nodes:

1. `renderTagFilterButtons()` — rendered the buttons and attached a dynamic-import listener to each: `import('./search.js').then(m => m.toggleTagFilter(tag))`
2. `initSearch()` — queried those same buttons and attached a second, synchronous listener

On **first load** (no stored data) `renderTagFilterButtons()` showed the "no tags" message, so `initSearch()` found no buttons. Tags added later in the same session only ever got the single dynamic-import listener. On **reload** (data already in storage) both ran in sequence, and each button ended up with two listeners.

On click, the synchronous listener fired and added the tag to `currentTagFilter`; then the dynamic-import `.then()` ran as a microtask (before any repaint) and toggled the same tag back off. The user always saw only the final state — no filter applied.

**Fix**

- `initSearch()` — replaced the per-button `querySelectorAll` loop with a single delegated listener on the `#tagFilters` container. The container is permanent; its buttons are replaced dynamically. Delegation handles any child button regardless of when it was created.
- `renderTagFilterButtons()` — removed the per-button listener attachment block entirely. Event wiring is now exclusively the responsibility of `initSearch()`.

### PDF export silently dropped images on macOS (`export.js`)

When exporting a task to PDF on macOS, the resulting file contained no images even though the same workflow worked correctly on Windows.

**Root cause — two compounding bugs**

1. **Shallow `childNodes` traversal** — `exportTaskAsPDF` iterated only the direct children of the temporary DOM element. On macOS, Chrome's `contenteditable` wraps pasted content in `<div>` block elements, so `<img>` nodes were nested one level deeper and never reached.

2. **Hardcoded `'PNG'` format in `doc.addImage`** — macOS clipboard (Preview, Keynote, etc.) puts `image/tiff` data URLs on the clipboard. Passing a TIFF data URL with the format forced to `'PNG'` causes jsPDF to fail silently inside its own `try/catch`.

**Fix**

Two private helpers were added before `exportTaskAsPDF`:

- `_normalizeImageToPng(dataUrl)` — converts any image format to PNG via `<canvas>` before passing to jsPDF; PNG and JPEG pass through unchanged.
- `_walkNodesForPDF(nodes, doc, taskId, margin, maxWidth, yPosRef)` — recursively walks a `NodeList`, handling text nodes, `<img>` elements (IDB lookup → `data-src` fallback → `src` fallback, all normalised through `_normalizeImageToPng`), and any other element by descending into its `childNodes`.

The flat `childNodes` loop in `exportTaskAsPDF` was replaced with a call to `_walkNodesForPDF`. Only `exportTaskAsPDF` was affected — the JSON/encrypted export paths use a separate `querySelectorAll('img')` (recursive) approach and were never broken.

### Notebook page content lost when IndexedDB is cleared (`repository.ts` + `notebook.js`)

When IndexedDB was cleared (browser cache wipe, IT policy, browser update), all notebook page content was silently lost even though page names and folder structure survived — because metadata lived in `localStorage` but content was stored only in IDB, loaded lazily on page open.

**Root cause**

On load, `storage.js` strips the `content` field from in-memory items so IDB content never reaches `localStorage`. Content had no fallback: `getNotebookItemContent()` tried IDB, then fell back to the `notebookItems` localStorage key — but that key never contained content either.

**Fix**

- `repository.ts` — `getNotebookItemContent()` extended with a third fallback tier: `localStorage.notebookContent_<id>` (raw HTML, not JSON-wrapped). Added `saveNotebookContentBackup(id, content)` and `deleteNotebookContentBackup(id)` exports.
- `notebook.js` — `saveAndClosePage()` calls `saveNotebookContentBackup()` on every save; `deleteNotebookItem()` calls `deleteNotebookContentBackup()` for every deleted page (including folder descendants) to keep localStorage clean.

Per-page keys (`notebookContent_<id>`) avoid re-serialising the entire notebook on every save — only the page being saved is written.
